# Speedchecker — سنجش زندهٔ سرعت اینترنت و ExpressVPN

نسخهٔ پایتونی Speedchecker برای سنجش سرعت اینترنت و مقایسهٔ مکان‌های ExpressVPN. پروژه یک
داشبورد زنده و واکنش‌گرا، رابط خط فرمان، گزارش JSON و حالت آزمایشی آفلاین دارد. نام ریپازیتوری
و بستهٔ پایتونی **speedchecker** است.

Python **۳٫۱۰ یا بالاتر** · مجوز MIT · قابل اجرا در Windows، macOS و Linux

## نصب و اجرا

```bash
git clone https://github.com/humorheatyt/speedchecker.git
cd speedchecker
python -m venv .venv
# macOS/Linux:
source .venv/bin/activate
# Windows PowerShell:
# .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python app.py
```

سپس **http://127.0.0.1:8000** را باز کنید. داشبورد در شروع روی حالت امن دمو است؛ با زدن
«شروع تست» می‌توانید رابط زنده را بدون تغییر شبکه یا VPN بررسی کنید. اعداد این حالت ساختگی و
با برچسب دمو مشخص‌اند. برای اندازه‌گیری واقعی، حالت دمو را خاموش کنید.

در داشبورد، دانلود/آپلود/Ping به‌صورت زنده، نمودار سرعت، نتایج هر مکان، دریافت گزارش JSON،
تعداد تکرار، اجرای ترتیبی یا هم‌زمان و تغییر واحد نمایش در دسترس است. واحد سرعت را می‌توان بین
`Mbps`، `MB/s`، `Kbps`، `KB/s`، `Gbps`، `GB/s`، `bps`، `B/s`، `KiB/s`، `MiB/s` و `GiB/s`
تغییر داد. واحد Ping هم `ms`، `s` یا `µs` است. با تغییر واحد، نمایش داشبورد همان لحظه عوض
می‌شود؛ دادهٔ اصلی برای دقت همیشه به Mbps نگهداری می‌شود.

## موتور Speedtest داخل خود پروژه است

کد متن‌باز **speedtest-cli نسخهٔ ۲٫۱٫۳** در مسیر `src/speedchecker/_vendor/` قرار دارد و همراه
ریپازیتوری و بستهٔ برنامه توزیع می‌شود؛ مجوز Apache-2.0 و اطلاعات منشأ هم کنار آن است. پروژه
مستقیماً از آن به‌عنوان کتابخانه استفاده می‌کند؛ بنابراین لازم نیست فایل اجرایی `speedtest` یا
بستهٔ PyPI به نام `speedtest-cli` را جداگانه دانلود/نصب کنید. فرمان
`python -m pip install -r requirements.txt` خود پروژه و وابستگی‌های داشبورد را نصب می‌کند.

این موتور، ابزار اختصاصی و رسمی Ookla نیست. اگر ابزار رسمی Ookla را از قبل دارید، رابط اختیاری
آن با `--speedtest-backend ookla` و پذیرش صریح مجوز با `--accept-license` قابل استفاده است؛ در
حالت پیش‌فرض هیچ ابزار Speedtest جداگانه‌ای لازم نیست.

> برای مقایسهٔ واقعی مکان‌های ExpressVPN، هنوز به اشتراک فعال ExpressVPN و نصب کلاینتی نیاز
> دارید که فرمان `expressvpnctl` را ارائه کند. Speedchecker سرویس VPN نیست. رابط گرافیکی و
> حالت دمو بدون ExpressVPN هم اجرا می‌شوند.

## تست واقعی مکان‌های VPN

۱. ExpressVPN را روی سیستم پشتیبانی‌شده نصب و فعال کنید. برنامه با رابط `expressvpnctl` کار
می‌کند؛ برای بررسی:

```bash
expressvpnctl get regions
expressvpnctl get connectionstate
```

۲. پیش از سنجش پایه، VPN فعلی را قطع کنید. در داشبورد حالت دمو را خاموش و تست را شروع کنید.
فرمان معادل خط فرمان:

```bash
speedchecker -s -r 3 locations.json
```

۳. اگر VPN وصل باشد، برنامه بدون اجازهٔ صریح آن را قطع نمی‌کند. برای اجازه، گزینهٔ
«اجازهٔ قطع VPN فعلی» را در رابط فعال کنید یا در خط فرمان `--disconnect-existing` بدهید.
اتصال اولیهٔ VPN **پس از پایان تست دوباره برقرار نمی‌شود**.

تست سرعت ممکن است حجم زیادی از اینترنت مصرف کند. اجرای ترتیبی `-s` معمولاً برای مقایسه
قابل‌اعتمادتر است، چون تست‌های هم‌زمان برای پهنای باند یک اتصال رقابت می‌کنند. اتصال به مکان‌ها
یکی‌یکی انجام می‌شود و بعد از هر تلاش، برنامه برای قطع اتصال تلاش می‌کند.

## فهرست مکان‌ها

فایل `locations.json` را مطابق مکان‌های موجود در کلاینت خود ویرایش کنید:

```json
{
  "locations": [
    {"country": "Netherlands", "city": "Amsterdam"},
    {"country": "Romania", "city": "Bucharest"},
    {"country": "Canada", "city": "Toronto"},
    {"country": "USA", "city": "New York", "region": "usa-new-york"}
  ]
}
```

`country` الزامی است و `city` و `region` اختیاری‌اند. شناسه‌های فعال را با
`expressvpnctl get regions` ببینید. اگر `region` بدهید، همان شناسه باید موجود باشد؛ در غیر این
صورت، شناسهٔ شهر-کشور بر شناسهٔ کشور اولویت دارد. مکان‌های نمونه تضمین نمی‌کنند که اکنون برای
حساب شما در دسترس باشند.

## گزینه‌های خط فرمان

```text
speedchecker [options] input_file
```

| گزینه | کاربرد |
| --- | --- |
| `-h`، `--help` | نمایش راهنما |
| `--version` | نمایش نسخه |
| `-s`، `--serial` | اجرای تست‌ها یکی‌یکی |
| `-r N`، `--repeat N` | تعداد تست هر مرحله؛ پیش‌فرض ۵ |
| `-o PATH`، `--output PATH` | مسیر گزارش جدید؛ فایل قبلی بازنویسی نمی‌شود |
| `--unit UNIT` | ثبت واحد دلخواه سرعت در تنظیمات گزارش |
| `--command-timeout SEC` | مهلت هر فرمان VPN؛ پیش‌فرض ۳۰ ثانیه |
| `--connection-timeout SEC` | مهلت انتظار اتصال/قطع؛ پیش‌فرض ۶۰ ثانیه |
| `--speedtest-timeout SEC` | مهلت هر تست سرعت؛ پیش‌فرض ۱۸۰ ثانیه |
| `--disconnect-existing` | اجازهٔ صریح برای قطع VPN قبلی |
| `--demo` | تست آفلاین با دادهٔ ساختگی و بدون تغییر شبکه |
| `--speedtest-backend bundled` | موتور داخلی پروژه (پیش‌فرض) |
| `--speedtest-backend ookla` | رابط اختیاری ابزار رسمی Ookla |
| `--accept-license` | پذیرش شرایط Ookla برای حالت اختیاری `ookla` |

روش‌های دیگر اجرا: `python app.py`، `python -m speedchecker` و نام‌های قدیمی
`vpnchecker` و `expressvpnspeedtest`. ابزار Speedtest داخلی را هم می‌توان با
`speedchecker-speedtest` اجرا کرد.

کد خروج: `۰` موفق، `۱` خطا یا نتیجهٔ ناقص، `۲` آرگومان نامعتبر و `۱۳۰` وقفه.

## گزارش و ایمنی شبکه

داشبورد آخرین گزارش را به‌صورت JSON برای دریافت ارائه می‌کند. خط فرمان به‌طور پیش‌فرض گزارش را
با نام `results-<UTC timestamp>.json` ذخیره می‌کند؛ مسیر `-o` نباید از قبل وجود داشته باشد.
گزارش پس از سنجش پایه و هر مکان به‌صورت اتمیک ذخیره می‌شود و نام دستگاه، سیستم‌عامل، تنظیمات،
سرعت خام، نمونه‌ها، اطلاعات مکان/سرور و خطاها را شامل می‌شود. پیش از انتشار گزارش آن را بررسی
کنید؛ فایل‌های پیش‌فرض `results-*.json` در Git نادیده گرفته می‌شوند.

سنجش پایه عمداً بدون ExpressVPN انجام می‌شود. اتصال VPN موجود تا وقتی اجازه ندهید دست‌نخورده
می‌ماند. VPN متصل‌شده توسط برنامه پس از تست قطع می‌شود و دوباره وصل نمی‌شود. Network Lock،
اتصال مجدد خودکار، VPNهای دیگر و پراکسی می‌توانند نتایج را تغییر دهند. در خط فرمان Ctrl+C و در
داشبورد «توقف ایمن»، ابتدا تست جاری را تمام و سپس برای پاک‌سازی اتصال تلاش می‌کنند؛ قطع اجباری
برنامه یا برق، تضمین پاک‌سازی ندارد.

`app.py` برای دسترسی پیش‌نمایش Arena و رابط‌های محلی روی `0.0.0.0` اجرا می‌شود. داشبورد را فقط
روی سیستم/شبکهٔ مورد اعتماد اجرا کنید؛ چون امکان شروع تست سرعت و اتصال VPN دارد. برای محدودکردن
اجرا به همان دستگاه، پیش از اجرا `SPEEDCHECKER_HOST=127.0.0.1` را تنظیم کنید. پورت را با
`PORT=8000` یا `SPEEDCHECKER_PORT` عوض کنید.

## توسعه و بررسی

```bash
python -m pip install -e '.[dev]'
python -m unittest discover -s tests -v
ruff check .
ruff format --check .
python -m build
```

تست‌ها با دادهٔ آفلاین و mock اجرا می‌شوند؛ نیاز به اشتراک ExpressVPN ندارند و تست واقعی
اینترنت انجام نمی‌دهند. رابط وب به CDN یا asset زمان اجرای خارجی وابسته نیست.
